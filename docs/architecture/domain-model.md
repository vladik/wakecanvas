# Domain model

WakeCanvas separates reusable software from each configured installation of that
software.

## Experience package

An Experience package is installed, versioned code and compiled assets. For
example, `org.wakecanvas.experience.living-gallery` version `1.0.0`. Installing it makes the
Experience available for configuration but does not run it or create workshop data.

## Experience instance

An Experience instance is created by an operator from an installed package. It has:

- an immutable, installation-local, positive integer instance ID;
- a human-friendly name such as “Friday Morning Workshop”;
- an Experience package ID and compatible installed version;
- validated Experience-defined configuration;
- an isolated SQLite database and media directory; and
- operational metadata such as creation time and last activation result.

Many instances can use the same package. Their configuration and data remain
isolated.

Instance IDs are generated by the platform database, are never reused after
deletion, and are not globally unique between kiosks. Human-friendly names are
editable and are never used as identifiers.

Archiving an instance is the normal operator action. It hides and disables the
instance while preserving its platform configuration, SQLite database, uploaded
media, and generated files so it can be restored after an accidental action.

Permanent purge is a separate maintenance action with stronger confirmation. It
deletes the archived instance and its complete isolated data directory, including
SQLite, uploaded media, generated files, caches, and platform-managed automatic
backups. A separately exported backup is outside WakeCanvas ownership and cannot
be removed automatically.

## Package removal

Uninstalling a package removes its compiled OTP application, browser assets, native
helpers, manifest, and unreferenced package cache. It does not silently delete
instances. The platform blocks uninstall while instances reference the package and
offers a separate, explicitly confirmed cascade operation to delete every instance
before uninstalling the package.

## Active instance

The kiosk has zero or one active instance. Activating an instance supplies an SDK
instance context to its Experience runtime and exposes that Experience's display,
intake, and operator surfaces. Deactivation stops the runtime and releases hardware.

```text
Living Gallery package 1.0
├── Morning Workshop instance ── own config, SQLite, and media
└── Evening Workshop instance ── own config, SQLite, and media

Kiosk active selection ─────────► exactly one instance
```
